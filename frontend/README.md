# TEAM / UP 프론트엔드

Notion 기획을 바탕으로 만든 Next.js 반응형 웹앱입니다. 게스트 모드와 소셜 로그인 기반 서버 모드를 제공합니다.

## 실행

```powershell
cd C:\Users\SSAFY\Desktop\teamup\frontend
npm.cmd install
npm.cmd run dev
```

터미널에 표시된 로컬 주소를 브라우저에서 엽니다. Windows에서 `npm` 스크립트 실행이 차단된 경우 `npm.cmd`를 사용할 수 있습니다.

## 현재 범위

- 모임 생성, 회원 추가·수정·비활성화, 참석자 선택, 임시 팀 편성·교환 및 경기 기록 조회
- 하단의 **홈 화면**에서 모임을 선택하고 **설명서**에서 사용 순서를 확인합니다. 경기 기록은 각 모임의 **이전 경기 기록**에서 조회합니다.
- 게스트 데이터는 서버에 전송하지 않고 해당 브라우저의 localStorage에 보관합니다. 브라우저 데이터를 삭제하거나 다른 기기를 사용하면 접근할 수 없습니다.
- 능력치는 바에서 1~10으로 선택합니다. 기존 API와 저장 데이터는 1~100 단위를 유지하며, 화면에는 10으로 나누어 표시합니다. 기존에 저장된 세부 점수는 바를 조절하기 전까지 그대로 유지합니다.
- 능력치를 모르는 회원의 임시 계산은 해당 회원을 제외한 활성 회원 평균에서 0.5점을 뺀 뒤 1~10 사이 정수로 반올림합니다. 기준 회원이 없으면 직접 선택합니다. 정책은 확정 전입니다.
- 게스트 편성은 브라우저 내 미리보기입니다. 로그인 모드는 서버에서 소유권·참석자·팀 인원을 검증합니다. 로그인 모드의 추가 조건에는 선수 2명의 같은 팀·다른 팀 관계와 포지션을 골고루 나누는 요청을 입력할 수 있습니다. 관계 조건은 필수로 지키고, 포지션 균형은 우선순위로 반영합니다. 최적해는 보장하지 않습니다.
- 추가 조건은 로컬 다국어 문장 임베딩으로 유형을 분류합니다. 선수 이름을 가린 문장만 내부 임베딩 서비스로 보내며, 서버가 실제 선수와 같은 팀·다른 팀 표현을 다시 확인합니다. 지원하지 않거나 충돌하는 조건은 거부합니다. 게스트 모드에서는 사용할 수 없습니다.
- 포지션 균형 조건은 축구의 `LWB`, `MF`, `LW`, `ST`와 농구의 `가드`, `센터`, `포워드`, `포인트가드`, `스몰포워드` 같은 세부 포지션을 인식합니다. `PG`와 `포인트가드` 같은 표기는 비교할 때만 같은 위치로 취급하며 회원 정보의 원래 표기는 유지합니다.
- 로그인 모드에서 팀 편성·교환 후 Claude가 팀별 핵심 선수와 전력 요약을 별도로 생성합니다. 입력된 이름·포지션·능력치·팀 평균이 Claude API로 전송됩니다. `.env`의 `ANTHROPIC_API_KEY`가 비어 있거나 AI 호출이 실패해도 편성 결과는 사용할 수 있습니다. 게스트 모드는 AI 분석을 제공하지 않습니다.
- 로그인 모드에서는 모임·회원 관리, 편성·서버 교환 검증, 경기 확정·기록 조회를 Spring API로 처리합니다. 게스트 데이터는 자동 업로드하거나 병합하지 않습니다.
- 로그인 시 세션 쿠키를 사용하고, 변경 요청마다 CSRF 토큰을 받아 전송합니다. 인증 토큰을 localStorage에 저장하지 않습니다.
- `MY`에서 종목별 내 이름·포지션·능력치·나이·메모를 저장할 수 있습니다. 같은 종목의 모임에서 내 회원 정보를 새로 등록하면 자동으로 입력되며 저장 전 수정할 수 있습니다. 다른 회원을 추가할 때는 빈 입력란을 선택합니다. 이미 등록된 모임 회원은 자동으로 변경되지 않습니다.
- 관리자는 모임 상세에서 재사용 가능한 초대 링크를 발급·비활성화할 수 있습니다. 초대받은 로그인 사용자는 멤버 목록과 경기 기록을 볼 수 있으며 자신의 이름·포지션·능력치·나이·메모만 등록·수정할 수 있습니다. 다른 회원의 나이와 메모는 관리자에게만 보입니다. 기존에 관리자가 입력한 회원은 이름이 같아도 자동 연결하지 않습니다.
- 새 링크를 발급하면 이전 링크가 무효화됩니다. 링크를 비활성화해도 이미 가입한 사용자는 유지됩니다. 서로 다른 기기에서 사용하려면 실제 접속 가능한 HTTPS 주소와 소셜 로그인 callback 설정이 필요합니다.
- 계정 삭제는 구현하지 않았습니다.
- 웹 매니페스트가 있지만 홈 화면 설치와 기기별 PWA 동작은 검증하지 않았으며 오프라인 사용을 제공하지 않습니다.
- 회원 관리에서 카카오톡 참여자 목록 캡처(PNG/JPEG/WebP) 또는 Excel(.xlsx)을 불러와 이름 후보를 선택하고, 포지션과 능력치를 직접 입력해 일괄 등록할 수 있습니다. 8MB 이하 파일을 지원하며 최대 100명을 한 번에 등록합니다. Excel은 첫 번째 시트의 선택한 열을 읽습니다.
- 사진은 로컬 Docker의 PaddleOCR에서 처리합니다. 첫 이미지 처리 시 한국어 모델을 내려받으므로 시간이 걸릴 수 있습니다. OCR 결과에 이름이 아닌 문구가 포함될 수 있으므로 직접 확인해야 합니다.

## 서버 연결

백엔드는 Java 25·MySQL 환경에서 `oauth` 프로필로 실행합니다. Next.js는 `/api`, `/oauth2`, `/login/oauth2`를 `BACKEND_URL`로 프록시하며 기본값은 `http://127.0.0.1:8080`입니다. 브라우저에서는 `http://localhost:3000`을 사용합니다.

백엔드 `.env`에 실제 제공자 인증 정보와 `APP_BASE_URL=http://localhost:3000`을 설정합니다. 제공자 콘솔 콜백도 `http://localhost:3000/login/oauth2/code/{google|kakao|naver}`로 맞춥니다. `APP_BASE_URL`을 바꾸면 콘솔 설정도 함께 변경해야 합니다.

로그인 후 모임·회원 관리 → 참석자 선택 → 편성 → 다른 팀 선수 2명 교환 → 결과 확정 → 경기 기록 조회 순으로 사용합니다. 기록 목록은 페이지 단위로 불러오며 ‘기록 더 보기’로 이어서 조회합니다. 같은 서버 입력의 재편성은 같은 후보를 반환합니다.

API 계약과 검증 범위는 [API 문서](../docs/API.md)를 참고하세요. 실제 제공자 로그인과 휴대폰 동작은 별도의 수동 검증이 필요합니다.

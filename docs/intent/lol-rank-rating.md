# 리그 오브 레전드 능력치의 티어 표시

- 확정일: 2026-11-24
- 상태: 구현 및 Docker 프런트엔드 반영 완료. 브라우저 수동 검증은 미완료.

## 목표 (Why)

리그 오브 레전드 이용자가 추상적인 숫자 능력치 대신 익숙한 롤 티어로 자신의 실력을 등록하고 확인할 수 있도록 한다. 기존 팀 편성 계산은 유지한다.

## 대상 (Who)

내 계정에서 롤 정보를 등록하는 사용자와 모임의 롤 회원 정보를 관리하거나 확인하는 사용자.

## 확정된 동작과 완료 기준 (Success)

- 롤의 능력치 입력은 숫자 슬라이더 대신 아래 10개 티어 선택으로 제공한다.
- 내 계정, 모임 회원 정보와 관련 능력치 표시에서 롤은 티어 이름으로 표시한다.
- 티어를 기존 화면 기준 1~10점에 순서대로 대응시켜 팀 편성 계산을 유지한다.
- 현재 코드에서는 화면의 1~10점을 내부 rating 10~100으로 저장하므로 이 저장 단위와 API 계약을 유지한다.
- 다른 종목은 기존 숫자 능력치 입력과 표시를 유지한다.

| 티어 | 화면 기준 점수 | 내부 rating |
| --- | --- | --- |
| 아이언 | 1 | 10 |
| 브론즈 | 2 | 20 |
| 실버 | 3 | 30 |
| 골드 | 4 | 40 |
| 플래티넘 | 5 | 50 |
| 에메랄드 | 6 | 60 |
| 다이아몬드 | 7 | 70 |
| 마스터 | 8 | 80 |
| 그랜드마스터 | 9 | 90 |
| 챌린저 | 10 | 100 |

## 제약 조건 (Constraint)

- 기존 프로젝트 구조와 rating 저장 단위를 존중한다.
- 티어와 점수의 대응은 이 프로젝트의 팀 편성용 규칙이며 실제 Riot MMR의 수치적 간격을 의미하지 않는다.
- 기존 데이터에 10 단위가 아닌 rating이 있을 수 있으므로 구현 시 이를 확인하고, 데이터 변경 없이 표시하는 방식을 검토한다.

## 하지 않을 것 (Out of scope)

- Riot API 연동, 소환사 계정 연결, 실제 티어 자동 조회.
- 티어 내부 단계(IV~I), LP, 언랭크 추가.
- 실제 MMR 추정이나 팀 편성 알고리즘 변경.
- 다른 종목의 능력치 체계 변경.
- 요청과 무관한 화면 구조 변경이나 대규모 리팩터링.

## 남은 수동 확인

브라우저에서 내 계정과 모임 회원의 롤 티어를 변경·저장하고 새로고침해 유지되는지 확인한다. 다른 종목은 숫자 슬라이더가 표시되는지, Excel 등록과 팀 편성 결과·경기 기록의 티어 표시가 올바른지 확인한다.

## 구현 결과와 검증

- `frontend/app/ratings.mjs`: 티어 이름과 숫자 표시 변환을 공통으로 관리한다.
- `frontend/app/RatingField.js`: 롤은 티어 선택, 다른 종목은 기존 숫자 슬라이더를 제공한다.
- 내 계정, 모임 회원 등록·목록, 참석자 선택, 팀 편성 결과, 경기 기록, Excel 회원 등록에 적용했다.
- 기존 중간값은 가까운 티어로 반올림해 `(환산)` 표시하며, 새 티어 선택 전에는 기존 값을 유지한다.
- 롤 팀 평균과 차이는 계산용 숫자로 유지하고 `평균 티어 점수`라고 표시한다.
- 롤의 모임 평균 기반 자동 능력치 입력은 숨겨 사용자가 티어를 선택하도록 했다.
- DB 스키마, API 계약, 팀 편성 계산 변경 없음.
- `node --test tests/ratings.test.mjs`: 4개 테스트 통과. 티어 대응, 중간값·하한값, 다른 종목 표시, 미등록 값 검증.
- Docker 빌드 이미지에서 `npm run lint` 통과, `npm run build` 통과.
- `docker compose up -d --build --no-deps frontend` 반영 완료.
- 연결된 브라우저가 없어 실제 내 계정 및 회원 정보의 티어 선택·저장 동작은 수동 검증하지 못했다.

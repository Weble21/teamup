# 모임 초대 링크 유지 및 모임 화면 복원

- 확정일: 2026-11-24
- 상태: 구현 및 Docker 반영 완료. 브라우저 직접 검증은 미완료.

## 목표 (Why)

모임 관리자가 초대 링크를 다시 공유하려고 새로 발급하는 불편을 없앤다. 새로고침이나 다른 기기 접속 후에도 기존 링크를 확인하고, 새로고침 후 현재 모임 상세 화면으로 돌아올 수 있게 한다.

## 대상 (Who)

초대 링크를 발급·조회·복사·비활성화하는 모임 관리자. 다른 기기에서도 동일한 계정으로 로그인하면 관리하는 모임의 기존 링크를 확인할 수 있어야 한다.

## 완료 기준 (Success)

### 초대 링크 유지

- 한 번 발급한 링크는 새로고침, 모임 재진입, 다른 기기에서 동일 계정으로 로그인한 후에도 화면에서 조회·복사할 수 있다.
- `새 링크 발급`을 누르면 기존 링크를 무효화하고 새 링크로 교체한다.
- `링크 비활성화`를 누르면 기존 링크를 무효화하고 화면의 링크를 제거한다.
- 새로고침, 조회, 모임 재진입, 접기·펼치기만으로 링크를 재발급하거나 무효화하지 않는다.
- 링크 조회 및 관리 권한은 해당 모임 관리자에게만 허용하고 서버에서 검증한다.
- 다른 기기에서 교체·비활성화한 결과는 이후 서버 조회 시 반영한다. 실시간 기기 간 동기화는 범위에 포함하지 않는다.

### 접기·펼치기

- 모임 초대 영역에 접기·펼치기 토글을 제공한다.
- 기본 상태는 펼침이다.
- 접어도 링크를 삭제하지 않고, 다시 펼치면 기존 링크를 표시한다.
- 토글은 키보드로 조작 가능하며 펼침 여부를 보조 기술에 알린다.

### 새로고침 후 화면 유지

- 모임 상세 화면에서 새로고침하면 목록으로 이동하지 않고 같은 모임 상세 화면으로 복원한다.
- 로그인·데이터 로딩 후 해당 모임에 접근할 수 있는지 확인한 다음 표시한다.
- 로그인 만료나 접근할 수 없는 모임의 경우 오류나 빈 화면 없이 로그인 또는 목록 화면으로 안내한다.

## 제약 조건 (Constraint)

- 현재 서버는 초대 토큰의 SHA-256 해시만 저장하며, 링크 조회 API는 없다. 다른 기기에서 원문 링크를 조회하려면 서버 저장·조회 구조를 변경해야 한다.
- 해시만 저장된 기존 링크의 원문은 복구할 수 없다. 변경 후 사용자가 한 번 새 링크를 발급한 시점부터 지속 조회를 지원한다. 조회 시 자동 재발급하지 않는다.
- 서버 저장 방식은 원문 복원 요구와 보안을 함께 고려해 구현 시 결정한다. 토큰은 로그나 오류 메시지에 노출하지 않는다.
- 기존 Controller-Service-Repository 책임 분리, 세션 인증, CSRF, 관리자 권한 검증을 유지한다.
- 기존 데이터와 UI 변경을 보존하고 필요한 범위만 수정한다.

## 하지 않을 것 (Out of scope)

- 모임 관리자 이외의 사용자에게 링크 관리·조회 권한 부여.
- 해시만 남아 있는 기존 링크의 원문 복원.
- 토글을 통한 링크 재발급·비활성화.
- 토글 접힘 상태의 기기 간 동기화.
- 기기 간 실시간 링크 상태 동기화.
- 미저장 폼, 미확정 팀 편성 결과 등 모든 임시 화면 상태의 영구 저장.
- 요청과 관계없는 인증 체계 교체나 전면적인 프런트엔드 리팩터링.

## 구현 결과

- `V8__persist_invitation_tokens.sql`에서 nullable `token` 컬럼을 추가했다. 기존 행과 해시는 보존하며 새 발급부터 원문을 함께 저장한다.
- Controller의 `GET /api/clubs/{clubId}/invitation` → `ClubInvitationService.getCurrent` → Repository/DB 순으로 조회한다. 관리자 검증은 Service에서 수행하고 응답은 DTO로 반환한다.
- GET/POST 토큰 응답에는 `Cache-Control: no-store`를 적용한다. 가입 검증은 기존 SHA-256 해시를 계속 사용한다.
- 조회 원문은 DB에 저장하므로 DB 및 백업 접근을 제한해야 한다. 브라우저 저장소에 원문을 영구 저장하지 않으며 토큰을 로그에 기록하지 않는다.
- `ClubInvitationPanel.js`는 모임 진입 시 기존 링크를 서버에서 읽고, 접기·펼치기·재발급·비활성화·복사를 처리한다. 모임별 컴포넌트를 분리해 다른 모임의 링크가 섞이지 않도록 했다.
- 링크 관리 영역은 기본 펼침이며 키보드 조작과 `aria-expanded`를 지원한다. 접어도 상태를 유지한다.
- `clubNavigation.mjs`와 `page.js`는 `?club={id}`로 모임 상세 위치를 표시한다. 로그인 후 조회한 접근 가능한 모임 목록과 ID를 대조하고 복원하며, 접근 불가 시 목록으로 안내한다.
- 게스트는 `guest=1`과 문자열 모임 ID를 사용해 기존 localStorage의 모임 상세를 복원한다.
- 기존 복사 버튼 위치, 1초 후 사라지는 알림 및 페이드 애니메이션, 화면 하단의 모임 수정 버튼을 유지했다.

## 검증 내역

- Java 25 환경에서 초대 관련 Service/Controller/HTTP 통합 테스트 12개 통과.
- HTTP 통합 테스트는 별도 H2 DB와 서로 다른 두 로그인 세션을 사용해 발급 후 동일 링크 조회, 재발급 후 이전 링크 거부, 비활성화 후 원문 제거·가입 거부, 관리자 권한, 미인증, CSRF를 확인했다. 실제 제공자 계정 로그인 테스트는 아니다.
- 로컬 전체 테스트는 기존 로컬 MySQL 인증 문제로 4개 실패했다. 현재 Docker DB에 연결해 전체 테스트를 재실행한 결과 총 163개 중 162개 통과, 선택 실행 테스트 1개 제외, 실패 0개였다.
- 프런트엔드 테스트 8개 통과. 새 화면 복원 테스트 4개는 접근 가능한 ID, 다른 계정의 ID 거부, 목록 이동 시 URL 정리, 게스트 ID 복원을 확인한다.
- 프런트엔드 lint 및 프로덕션 빌드 통과.
- Docker DB V8 적용, 백엔드의 마이그레이션 8개 검증 및 정상 기동 확인. 기존 볼륨은 보존했다.
- 백엔드·프런트엔드 Docker 반영 완료.

## 남은 수동 확인

연결된 브라우저가 없어 실제 로그인 화면 조작, 새로고침 및 토글의 시각적 동작은 직접 검증하지 못했다. 브라우저에서 새 링크를 발급한 뒤 같은 모임을 새로고침하고, 다른 기기로 같은 계정에 로그인해 링크가 같은지 확인한다. 접기·펼치기와 복사 알림을 확인하고, 재발급·비활성화 후 다른 기기에서 모임에 다시 진입했을 때 변경된 상태가 표시되는지 확인한다.

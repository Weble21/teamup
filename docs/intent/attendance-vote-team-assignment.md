# 운동 일정 투표와 팀 나누기 연동: 작업 의도

## 목표

운동 일정 투표가 종료되면 참석 응답을 팀 나누기에 활용하고, 팀을 확정한 결과를 해당 운동 일정의 경기 기록으로 저장한다.

## 확정된 요구사항

- 사용자가 제공한 그림처럼 운동 일정 투표 목록과 상세 화면에 팀 나누기 버튼을 배치한다.
- 투표가 종료된 후에 버튼을 활성화하며, 기존 팀 편성과 마찬가지로 모임장만 이용한다.
- 투표에서 참석을 선택한 사용자를 팀 편성 화면에 자동 선택한다. 모임장은 실제 상황에 맞게 참석자를 추가하거나 제외할 수 있다.
- 참석 응답자의 해당 모임 선수 프로필이 없거나 비활성화된 경우, 모임장에게 해당 사람과 이유를 알리고 자동 선택에서는 제외한다. 편성 가능한 참석자만 선택한 뒤 모임장이 명단을 조정해 진행한다.
- 운동 일정 하나당 경기 기록은 최대 하나만 저장한다. 이미 확정된 일정에서는 중복 기록을 생성하지 않고 기존 경기 기록을 확인할 수 있게 한다.
- 팀 확정 시 결과를 이전 경기 기록에 저장하고 해당 기록 화면으로 이동한다.
- 모임 상세의 기존 독립적인 빠른 팀 편성은 유지한다.

## 이번 작업의 범위 밖

- 투표의 선택 항목이나 댓글 기능 변경.
- 기존의 빠른 팀 편성 알고리즘 변경.
- 보관된 옛 운동 일정 조회 화면이나 모바일 홈 화면 설치 기능.

## 구현 시 확인 사항

- 참석 응답은 사용자 계정이고 팀 편성에는 해당 모임의 선수 ID가 필요하므로, 동일 모임의 계정 연결과 활성 상태를 확인해 변환한다. 이름이 같은 선수끼리 이름만으로 연결하지 않는다.
- 클라이언트 표시뿐 아니라 서버에서 모임장 권한, 투표 종료 상태, 투표와 모임의 관계를 검증한다.
- 경기 기록과 운동 일정의 연결을 영속화하고, 중복 요청과 동시 확정에도 일정 하나당 기록 하나가 유지되도록 데이터베이스 제약과 트랜잭션을 검토한다.
- 사용자가 참석자 선택을 조정한 결과를 기존 팀 편성 검증에 전달하고, 경기 확정 후 이전 기록 조회·화면 이동을 확인한다.
- 기존 운동 일정, 선수 정보, 경기 기록을 보존하며 마이그레이션한다.
- 목록과 상세의 버튼 위치는 사용자가 제공한 그림을 참고한다.

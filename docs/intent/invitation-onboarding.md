# 초대 링크 로그인·종목 정보 등록·가입 흐름

- 확정일: 2026-11-24
- 상태: 변경된 요구사항까지 구현 및 Docker 반영 완료. 실제 제공자 로그인·브라우저 조작 검증은 미완료.

## 목표 (Why)

초대받은 사용자가 로그인 및 해당 종목의 내 정보 등록을 거쳐 모임에 가입하도록 안내한다. 초대 수락 시 등록한 내 정보를 모임 선수 정보로 자동 등록해 중복 입력을 없앤다. 이미 가입한 사용자는 불필요한 등록·가입 절차로 보내지 않는다.

## 대상 (Who)

초대 링크로 모임에 가입하려는 사용자. 로그인하지 않은 사용자와 이미 로그인한 사용자, 이미 해당 모임에 가입한 사용자를 포함한다.

## 확정된 흐름과 완료 기준 (Success)

1. 초대 링크를 열면 로그인 상태를 확인한다.
2. 미로그인이라면 로그인 화면을 표시하며 초대 정보를 로그인 이후까지 유지한다. 이미 로그인했다면 바로 다음 단계로 진행한다.
3. **로그인 이후**, 유효한 초대 링크의 모임에 이미 가입했는지 서버에서 확인한다.
4. 이미 가입했다면 **`이미 가입된 모임입니다!`** 안내를 표시한다. 종목 정보 등록 또는 초대 수락을 다시 요구하지 않고, 회원·선수 정보를 추가 생성하거나 덮어쓰지 않는다. 단순히 알림창을 통해 회원에게 알려만 주고, 이후의 다른 기능은 해당되지 않는다.
5. 미가입 상태라면 초대된 모임의 종목과 일치하는 계정의 종목별 내 정보가 등록되어 있는지 확인한다.
6. 해당 종목 정보가 이미 있으면 초대 수락 화면을 바로 표시한다.
7. 해당 종목 정보가 없으면 먼저 해당 종목의 내 정보 등록 화면을 표시한다. 등록을 완료하면 초대 수락 화면을 표시한다.
8. 사용자가 **초대 수락 버튼을 눌렀을 때** 가입을 처리하고, 저장된 종목별 내 정보를 해당 모임의 본인 선수 정보로 자동 등록한다. 로그인이나 내 정보 저장만으로 자동 가입시키지 않는다.
9. 해당 계정과 연결된 모임 선수 정보가 이미 있다면 덮어쓰지 않는다. 가입 및 선수 등록을 반복 요청해도 중복 생성하지 않는다.

## 제약 조건 (Constraint)

- 가입 여부 확인은 반드시 로그인 이후 인증된 사용자 ID를 기준으로 서버에서 수행한다. 미로그인 상태에서 특정 사용자의 가입 상태를 판단하지 않는다.
- 모임 관리자는 이미 접근 권한이 있는 사용자로 취급하고 자기 모임에 중복 가입시키지 않는다.
- 무효화되거나 교체된 초대 링크는 가입에 사용할 수 없다. 최초 조회 후 수락 전에 링크 상태가 바뀌는 경우에도 서버에서 최종 검증한다.
- 가입과 본인 선수 정보 자동 등록은 데이터 정합성과 반복·동시 요청을 고려해 처리한다. 한쪽만 저장되는 부분 성공을 방지한다.
- 관리자가 이름만 입력해 둔 기존 선수는 이름이 같다는 이유로 사용자 계정에 자동 연결하지 않는다. 기존 계정 연결·비활성 상태를 임의로 바꾸지 않는다.
- 내 정보 등록과 초대 수락의 취소·오류 시 초대가 임의로 수락되거나 유실되지 않도록 한다.
- 종목별 내 정보 및 모임 선수 정보는 기존 필드와 Validation을 사용한다. 롤은 기존 티어 입력·표시를 유지한다.
- Controller-Service-Repository 책임 분리와 세션 인증·CSRF·권한 검증을 유지한다.
- 안내 팝업은 모달로 띄운다.
- 이미 가입한 경우 안내 후 어떤 화면으로 이동할지는 기존 모임 화면 흐름에 맞춰 구현하되, 재가입·정보 등록을 요구하지 않는 기준을 지킨다.

## 하지 않을 것 (Out of scope)

- 로그인 없이 모임 가입 또는 특정 사용자의 가입 여부 조회.
- 로그인 성공이나 내 정보 저장만으로 사용자 확인 없이 가입 처리.
- 다른 종목의 정보를 대신 사용하거나 필수 정보를 임의 생성.
- 계정의 내 정보를 수정할 때마다 기존 모임 선수 정보를 자동 동기화.
- 이름이 같은 기존 선수를 사용자 계정에 자동 연결하거나 기존 선수 정보를 덮어쓰기.
- 기존 OAuth 제공자 설정이나 인증 방식 교체.
- 요청과 관계없는 화면 전면 개편 및 대규모 리팩터링.

## 구현 전 인계 내용

이 파일을 읽고 초대 진입·OAuth 복귀·종목별 내 정보·모임 가입·본인 선수 등록의 현재 코드를 확인한 뒤 구현한다. 로그인 여부, 기존 가입 여부, 종목 정보 유무에 따른 분기와 무효 링크·반복·동시 요청을 검증한다. 로그인 후 가입 상태 및 종목을 확인할 수 있도록 필요한 서버 API를 추가하고, 프런트엔드에서 초대 흐름을 유지한다. 기존 초대 링크 저장·접기/펼치기·모임 상세 새로고침 복원 기능도 보존한다. 구현 후 검증 결과와 브라우저 직접 확인 여부를 구분해 기록하고 Docker에 반영한다.

## 구현 결과

- `POST /api/invitations/preview`: 로그인·CSRF 확인 후 유효한 초대의 모임 이름·종목, 본인 가입 여부, 해당 종목의 내 정보 등록 여부를 반환한다. 가입·회원 정보는 변경하지 않는다. 토큰은 POST 본문에만 전달하고 응답은 `no-store`를 적용한다.
- `ClubInvitationController` → `ClubInvitationService.preview/join` → Repository 순으로 역할을 분리했다. `InvitationOnboardingResponses.kt` DTO를 사용한다.
- `InvitationOnboarding.js`가 로그인 후 초대를 확인한다. 미가입자는 종목 정보가 없으면 등록 폼, 있으면 수락 화면을 표시하며 직접 수락하기 전에는 가입시키지 않는다. 롤 입력에는 기존 `RatingField`를 사용한다.
- 기존 가입자(관리자 포함)는 `이미 가입된 모임입니다!` 안내 모달만 표시한다. 목록을 기본 화면으로 사용하며 해당 모임 상세로 자동 이동하거나 정보 등록·가입을 다시 수행하지 않는다.
- 새 가입은 멤버십과 계정에 연결된 선수 정보 생성을 하나의 트랜잭션으로 처리한다. 기존 연결 선수의 내용·비활성 상태는 보존하고, 이름만 같은 미연결 선수를 자동 연결하지 않는다.
- 가입 시 모임 → 초대 순서로 잠금을 잡고 `READ_COMMITTED`에서 앞선 요청의 가입 결과를 확인한다. 수락 시 초대 유효성과 현재 모임 종목의 내 정보를 다시 검사한다.
- `page.js`는 sessionStorage에 초대를 유지해 로그인 복귀와 새로고침을 지원한다. 같은 탭에서 fragment만 바뀌는 새 초대 링크도 다시 진입 처리한다. 명시적인 취소·성공·기존 가입 확인 시 초대를 제거한다.
- 처리 중 로그인 만료 시 초대를 보존하고 로그인 화면으로 안내한다. 화면 이탈 시 요청을 취소하고, 늦은 응답이 이전 초대 화면으로 되돌리지 않도록 처리했다.
- 문서 변경을 다시 읽어 초대 안내를 `AlertModal.js`의 중앙 모달로 바꿨다. 기본 1초 후 닫기와 180ms 페이드 업·다운을 유지하며 확인 버튼·Escape로도 닫을 수 있다. native dialog를 사용해 배경 조작을 막고 포커스를 모달 안에 둔다. 내 정보 입력·수락 화면은 자동으로 닫지 않는다.
- 기존 초대 링크 조회·접기/펼치기, 복사 알림, 모임 상세 새로고침 복원을 보존했다. 이번 변경을 위한 추가 DB 스키마 변경은 없다.

## 검증 결과

- Docker MySQL 환경 전체 백엔드 테스트: **173개 중 172개 통과, 선택 실행 테스트 1개 제외, 실패 0개**.
- Service/HTTP 초대 테스트 21개 통과: 가입자 우선 분기, 종목 정보 미등록·다른 종목 차단, 등록 후 수락, 필드 복사, 기존 선수 정보 보존, 중복·동시 가입, 수락과 비활성화 경합, CSRF·인증 검증 등을 확인했다.
- 실제 MySQL 테스트를 추가 실행해 동일 계정의 동시 수락 4개 요청 중 최초 1개만 신규 가입하고 나머지 3개는 기존 가입으로 반환함을 확인했다. 멤버십과 연결 선수는 각각 1개이며, 테스트가 생성한 ID에 해당하는 데이터만 정리했다.
- 프런트엔드 테스트 10개 통과. 기존 가입자는 종목 정보 유무와 관계없이 등록·수락을 건너뛰는 분기를 포함한다.
- 프런트엔드 프로덕션 빌드·lint 통과. lint에서 발견한 초기 로딩 상태 갱신은 API 응답 콜백으로 정리했다.
- Docker 백엔드·프런트엔드 반영 완료. 백엔드 정상 기동, 기존 마이그레이션 8개 검증, 프런트엔드 HTTP 200 및 미인증 사용자 조회 HTTP 401을 확인했다.
- API 계약은 `docs/API.md`, `docs/openapi.json`에 반영했다.

## 남은 수동 확인

연결된 브라우저가 없어 실제 카카오 계정 로그인·복귀와 화면 조작은 직접 확인하지 못했다. 테스트에서는 인증된 principal을 사용했으며 실제 제공자 로그인 성공을 의미하지 않는다. 다음 경로를 브라우저에서 확인한다.

- 미로그인 상태로 초대 열기 → 로그인 → 해당 종목 정보가 없으면 등록 → 수락 → 본인 선수 자동 등록.
- 해당 종목 정보가 있는 계정 → 바로 수락 화면 표시.
- 이미 가입한 계정 및 관리자 → 안내 모달만 표시하고 모임 상세 자동 이동·정보 재등록 없음.
- 등록 폼에서 취소·새로고침, 처리 중 로그인 만료, 같은 탭에서 다른 초대 열기, 무효 링크 안내.
- 안내 모달의 중앙 배치·1초 자동 닫기·페이드 효과와 기존 알림·초대 패널의 표시.
